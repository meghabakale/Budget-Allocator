Enhance and implement a production-grade system for:

"Real-Time Collaborative Budget Allocation System with Multi-Admin Architecture and Conflict Arbitration"

---

🔷 CORE OBJECTIVE

Build a scalable system where:

- Multiple Admins manage departments based on location
- A central Finance Manager controls the global budget pool
- Budget distribution across admins is NOT equal, but dynamically determined based on:
  - priority
  - demand (requirements)
  - performance (optional)
- Conflicts are automatically resolved
- All changes trigger cascading recalculation
- The system remains real-time, auditable, and consistent

---

🔷 ROLE STRUCTURE

1. Finance Manager (Super Admin)

- Controls global budget pool
- Reviews budget demands from all admins
- Allocates budget dynamically across admins
- Can override any allocation
- Has full system visibility

---

2. Admin (Location-Based)

- Each admin is assigned a location:
  
  - Pune
  - Delhi
  - Bangalore
  - Chennai

- Responsibilities:
  
  - Manage departments in their location
  - Collect and submit aggregated budget demand
  - Approve/reject department requests
  - Handle negotiation and conflict resolution

---

3. Department Head

- Registers with:
  - department name
  - location
- Automatically assigned to corresponding admin based on location

---

🔷 LOCATION-BASED AUTO ASSIGNMENT

When a Department Head registers:

- System maps location → admin
- Automatically assigns:
  - user.adminId
  - department.adminId

---

🔷 BUDGET DISTRIBUTION MODEL (CRITICAL – REAL-WORLD LOGIC)

❌ Do NOT use equal distribution across admins

✅ Use dynamic allocation based on:

1. Priority

- Strategic importance of location

2. Demand (Requested Budget)

- Total requests from departments under each admin

3. Performance (Optional Advanced Feature)

- Historical utilization efficiency

---

🔷 ALLOCATION WORKFLOW

1. Finance Manager sets total budget:
   Example:
   Total Budget = ₹100L

2. Each Admin submits demand:
   Pune → ₹40L
   Delhi → ₹30L
   Bangalore → ₹50L
   Chennai → ₹20L

3. System detects over-demand (₹140L > ₹100L)

4. Apply weighted allocation model:

Example formula:
Final Allocation Score =
(0.5 × priority_score) +
(0.3 × demand_score) +
(0.2 × performance_score)

5. System distributes budget dynamically:
   Example:

- Bangalore → ₹40L
- Pune → ₹30L
- Delhi → ₹20L
- Chennai → ₹10L

6. Finance Manager can:

- Accept system recommendation
- Override allocations manually

---

🔷 DYNAMIC REALLOCATION (ADVANCED FEATURE)

- If any admin underutilizes budget:
  - Remaining funds are redistributed
- Trigger recalculation across all admins

---

🔷 CONFLICT ARBITRATION ENGINE

Rules:

1. Higher priority wins
2. If equal priority → earlier request wins
3. Else → admin/manual resolution

---

🔷 CASCADING RECALCULATION ENGINE

Trigger on:

- request create/update
- admin allocation changes
- conflict resolution
- rollback

Must:

- recalculate all allocations
- update remaining budget
- re-evaluate all pending requests
