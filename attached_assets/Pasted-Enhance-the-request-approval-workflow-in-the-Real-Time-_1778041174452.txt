Enhance the request approval workflow in the:

"Real-Time Collaborative Budget Allocation System"

to enforce a proper enterprise-grade request lifecycle.

---

🔴 PROBLEM TO FIX

Current behavior:

- When a Department Head submits a budget request
- The system automatically approves the request ❌

This is incorrect and violates real-world financial governance.

---

🎯 OBJECTIVE

Modify the system so that:

- Every newly created request starts in a controlled approval state
- No request is automatically approved upon submission
- Admin review and approval are mandatory
- Status transitions properly reflect negotiation, conflict, and re-approval workflows

---

🔄 UPDATED REQUEST WORKFLOW

1. Department Head submits request

When a request is created:

DO NOT:

- auto-approve
- auto-allocate budget

Instead:

- set status = PENDING
- allocatedAmount = 0

---

🟡 REQUIRED STATUS SYSTEM

Implement the following statuses:

1. PENDING

- Initial state after request creation
- Awaiting admin review

---

2. UNDER_REVIEW

- Admin is actively reviewing request

---

3. UNDER_NEGOTIATION

- Request is under discussion between:
  - Admin
  - Department Head

---

4. CONFLICTED

- Budget conflict detected
- Insufficient funds or overlapping requests

---

5. CRITICAL

- High-priority request requiring urgent admin attention
- Used for emergency or high-priority allocations

---

6. PENDING_REAPPROVAL

- Request became eligible after recalculation
- Still requires explicit admin approval

---

7. APPROVED

- Admin manually approved request

---

8. REJECTED

- Admin rejected request

---

⚙️ STATUS TRANSITION RULES

PENDING
→ UNDER_REVIEW
→ UNDER_NEGOTIATION
→ APPROVED / REJECTED / CONFLICTED

CONFLICTED
→ PENDING_REAPPROVAL
→ APPROVED / REJECTED

CRITICAL
→ prioritized in review queue

---

🛡️ APPROVAL RULES (STRICT)

- ONLY Admin can approve requests
- Department Heads cannot self-approve
- Recalculation engine must NEVER auto-approve
- Budget eligibility ≠ approval

---

🖥️ UI REQUIREMENTS

1. Requests Table:

- Show status badges with colors:
  
  - Blue → Pending
  - Orange → Under Review
  - Yellow → Under Negotiation
  - Red → Conflicted
  - Purple → Critical
  - Cyan → Pending Re-Approval
  - Green → Approved
  - Gray → Rejected

---

2. Admin Dashboard:

- Separate queues for:
  - Pending Requests
  - Critical Requests
  - Re-Approval Queue
  - Negotiation Queue

---

3. Department Dashboard:

- Show current request status timeline
- Show admin comments/reasons

⚠️ BUSINESS RULES

- No request should bypass admin approval
- Every request must follow lifecycle states
- Critical requests receive priority handling
- All transitions must be logged and traceable

---

🎯 FINAL GOAL

Implement a realistic financial approval workflow where:

- Requests begin as PENDING
- Admin review is mandatory
- Negotiation and conflicts are reflected through proper statuses
- No automatic approvals occur
- System behavior matches enterprise financial governance standards
